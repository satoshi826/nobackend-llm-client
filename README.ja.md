# nobackend-llm-client

[English](README.md) | **日本語** | [简体中文](README.zh-CN.md)

> 自分の API キーで、サーバーなしに、ブラウザだけで動く LLM チャット。

サーバーを持たず、ログも残さない LLM チャットクライアントです。規制の少ないモデルやオープンなモデルを使いたいけれど、SaaS に会話を残したくない人のためのものです。自分でサーバーを運用したり、ローカルで LLM を動かしたりする必要はありません。

- **サーバーなし**: 静的ファイルだけで動きます。ブラウザから、あなたのキーで LLM の提供元の API に直接つなぎます。アカウント登録・解析ツール・外部スクリプトはありません。
- **データは手元だけ**: 会話と設定は、ブラウザの中（IndexedDB）にだけ保存します。
- **キーを盗まれにくく**: API キーは別ページの「キー金庫」だけが持ち、アプリ本体には渡りません。金庫は、ビルド時に決まった各提供元のホスト宛てにだけキーを付けます。厳格な CSP と Trusted Types も使っています。
- **パスフレーズ（任意）**: 設定すると、API キーと会話の両方を暗号化して保存し、解錠するまでアプリ全体をロック画面で隠します。

画面は日本語・英語・中国語（簡体字）に対応しています（ブラウザに合わせて自動、または「設定 → 表示」で選択）。設計の原則と決まりは [docs/principles.md](docs/principles.md)（英語）にあります。

セキュリティの設計が何を守り、どこから先は守れないかは [docs/security.ja.md](docs/security.ja.md) にまとめています。

## できること

- **接続先**: Venice、OpenRouter、Anthropic、Google Gemini、OpenAI、DeepSeek、Groq、NanoGPT、DeepInfra、Cerebras、Novita、Chutes、Together と、ビルド時に足す OpenAI 互換の接続先（Ollama など）。特別扱いの接続先はなく、最初に使う接続先を選びます。
- **モデル一覧**: ブックマーク（接続先をまたいで☆を付けたモデル）、並び替え（おすすめ・名前・価格・コンテキスト長）と絞り込み（private・思考・画像・検索・無料）ができ、価格と能力も表示します。
- **チャット**: ストリーミング、思考の表示、Markdown とコードのハイライト、会話ツリー（再生成・編集・別のモデルで再生成）、どこにも保存しない一時チャット（最初のメッセージの前に、チャットのヘッダーで切り替え）。
- **サンドボックス**: HTML と SVG のファイルはページとして表示し、html・svg・js のコードブロックには「実行」ボタンが付きます。チャットのモデルは正確な計算などに JavaScript を実行できます（`run_javascript`、実行前に確認）。どれもアプリに触れられず、通信を止めた隔離された枠の中で動きます（WebRTC による通信は、それを止めるブラウザでだけ止まります。Chrome では止まりません）。
- **ファイル**: 「レポートにまとめて」のように頼むと、モデルが文書（Markdown・CSV など）を「ファイル」タブに保存します。長い文書は分けて書きます。ファイルは直前の版を 1 つ残すので、最後の変更を「元に戻す」で取り消せます。会話のファイルは、最初のファイルと一緒にできる作業フォルダ（名前はモデルが付けます）に入り、モデルが読み書きできるのはその中（と会話に添付したファイル）だけです。ツールはコーディングエージェントと同じ形です（パターンでの一覧、行の検索、行番号付きの読み込み、書き込み、置き換え、追記、移動、削除。削除は毎回確認します）。モデルは作ったページを開いて、エラーや表示された文字を確かめて直せます（preview_page）。同じエラーはプレビューの上にも数が出て、押すと一覧で見られます。「ファイル」タブの「このフォルダで会話する」で、既存のフォルダを使う新しい会話を始められます。ファイル名にはフォルダを含められ（`site/css/style.css`）、HTML のページは、同じサイト（ページから上にたどって最初の index.html のあるフォルダ）のファイル（CSS・JavaScript のモジュール・画像）を読み込んでプレビューできます（ネットには接続しません）。ページの localStorage はサイトの localStorage.json に保存され、開き直しても残ります（消すとデータがリセットされます）。「ファイル」タブはファイラー（フォルダ・種類・会話ごとの表示、新しいフォルダ、名前変更、メニューやドラッグでのフォルダへの移動、フォルダごとの削除、項目ごとのメニューと右クリック、カード／一覧表示、並び替え、中身も対象の検索、種類別・会話別の表示、複数選択、ドロップでの取り込み）です。テキスト・CSV・コード・PDF（文字はブラウザ内で抽出）を、端末や保存済みファイルから添付できます。表示・編集・ダウンロード・印刷（PDF 保存）に対応。
- **画像生成**（Venice、OpenAI、Gemini、OpenRouter、NanoGPT、DeepInfra、Together。指示での編集は Gemini、NanoGPT、OpenAI、OpenRouter、Venice。高解像度化と背景除去は Venice）: 入力欄の画像モード（モデル・縦横比・解像度・1〜4 枚・スタイル・ネガティブプロンプト・シード）、「同じ設定でもう一度」「似た画像を作る」、高解像度化・編集・背景除去、ギャラリー、チャットのモデルが画像を作れるツール（任意）。画像は端末内に保存し、パスフレーズがあれば暗号化します。
- **動画生成**（Venice、OpenRouter、Gemini）: 入力欄の動画モード。どれかのキーを入れると表示されます（モデル・長さ・解像度・縦横比・音声・最初の場面。画像から動き出す動画も作れ、画像には「動画にする」が付きます）。送る前に料金を表示します。作成はサービス側で数分続き、ページを読み込み直しても続きを待てます（Venice・OpenRouter）。待つのをやめて、あとでまた待つこともできます。動画は画像と一緒に保存します。
- **返信候補**: 最新の回答の下に、次に送りそうな短い返信を出します。押すと入力欄に入ります。候補の数、参考にする直前のやり取りの回数、使うモデルを設定できます。
- **Web**: 接続先の内蔵検索（Anthropic、Gemini、Groq、OpenRouter、Venice）か Tavily のツールで検索。モデルは `fetch_url` でページ（HTML・テキスト・PDF）を読み、別の呼び出しが知りたいことだけを抜き出してからモデルに渡します（Claude Code の WebFetch と同じ方式）。`fetch_file` でファイルを取り込めます。取得はすべて取得用ページで確認し、許可したサイトは覚えておけます。
- **スキル**: SKILL.md 互換の手順書です。モデルは必要なときだけ本文を読み込み、`/名前` で自分で指定することもできます。会話の中で「スキルにして」と頼むと、モデルが下書きを作り、あなたの承認のあとで保存します。
- **長い会話**: 会話の圧縮（手動・自動）、プロンプトキャッシュ、コンテキスト長の安全装置。
- **使用量**: 費用とトークン数の推移と、モデル・接続先・用途・会話ごとの内訳を出します。記録はこのブラウザの中だけです。DeepSeek・NanoGPT・OpenRouter（このキーの上限の残り）・Venice は残高も表示します。
- **データ**: 全文検索、JSON のバックアップと読み込み（パスワードで暗号化も可）、画像の削除、全データ削除、PWA、ダークモード、モバイル表示。
- **開発者向け**: 返答ごとに、接続先へ送ったリクエスト（JSON）を表示できます（設定 → 情報 →「送ったリクエストを表示する」）。

### 実際の API を使わずに試す（モックサーバー）

```bash
npm run mock      # Venice / Anthropic / Gemini / OpenRouter / OpenAI / Tavily / Jina Reader 互換のモック（:8787）
VITE_VENICE_BASE_URL=http://localhost:8787/api/v1 \
VITE_ANTHROPIC_BASE_URL=http://localhost:8787/anthropic/v1 \
VITE_TAVILY_BASE_URL=http://localhost:8787/tavily \
VITE_JINA_BASE_URL=http://localhost:8787/jina \
npm run dev
```

**モックのキー**: Venice は `mock-key`、Anthropic は `mock-ant`、Tavily は `tvly-mock`。Gemini（`mock-gem`）・OpenRouter（`mock-or`。モデル一覧・残高・画像・動画だけ）・OpenAI（`mock-oai`）は、`VITE_GEMINI_BASE_URL=http://localhost:8787/gemini/v1beta`、`VITE_OPENROUTER_BASE_URL=http://localhost:8787/openrouter/api/v1`、`VITE_OPENAI_BASE_URL=http://localhost:8787/openai/v1` で使えます。モックは Venice の画像モデルも返して PNG を作ります。3 つの動画 API の作成も受け付け、何度か問い合わせると短い動画を返します。画像のプロンプトに `違反` を含めるとコンテンツポリシーによる拒否（言い換えの提案付き）、`ぼかし` を含めるとぼかした結果が返り、チャットのモデルに「絵を描いて」と頼むと（画像のツールがオンなら）`generate_image` を呼びます。

**メッセージ中のキーワード**でモックの動きが変わります。

- 全般: `思考` / `think`、`コード`、`長文`、`エラー`、`残高`、`画像`、`xss`、`盗用`
- ツール方式の Web 検索: `検索`、`読んで`（検索のあと）。ページを直接読む: `ページを読んで`
- 内蔵の検索（Anthropic と Gemini のモック）: `検索` / `天気`
- スキル: `スキル` で一覧の先頭のスキルを読み込む
- skill-creator を使った会話: `作って` / `直して` で save_skill を呼ぶ
- ファイル: `レポートにまとめて` で write_file を呼ぶ。会話にファイルがあれば、`追記して` / `結論を直して` / `全部読んで` で append_file / edit_file / read_file を呼ぶ
- サンドボックス: `実行できる例` で実行できる JS と HTML のコードブロックを返し、`計算して` で run_javascript を呼び、`ページを作って` で HTML ファイルを作る

## デプロイ（GitHub 連携で Cloudflare Workers）

静的ファイルだけを配る Worker として動かします（`wrangler.jsonc`。Worker のコードはありません）。キー金庫（`/vault/`）と取得用ページ（`/fetch/`）も同じサイトから配信します。

1. このリポジトリを GitHub に push する。
2. Cloudflare のダッシュボードで Workers & Pages → Create → **Import a repository** を開き、リポジトリを選ぶ。
3. プロジェクトを設定する。
   - **Project name**: `wrangler.jsonc` の `name`（`nobackend-llm-client`）と同じにする。
   - **Build command**: `npm run build`。`wrangler.jsonc` でも実行されるので、空のままでも動きます。
   - **Deploy command**: `npx wrangler deploy`（既定のまま）。
   - **環境変数**: なし。Node 22 は `.node-version` で指定しています。`VITE_*_BASE_URL` は**設定しないでください**（モック用です）。
4. 以後は `main` への push のたびに `https://<名前>.<アカウント>.workers.dev` へデプロイされます。

**Cloudflare 側でオフにする機能**: Web Analytics、Rocket Loader、Email Address Obfuscation、Zaraz。どれもスクリプトを差し込むため CSP で止まり、「外部スクリプトなし」の方針にも反します。

**確認**: 各ページに CSP が 1 つずつ付き、金庫のページには金庫用の CSP（`connect-src` に LLM の API）が付いていることを確かめます。

```bash
curl -sI https://<サイト>/ | grep -i content-security-policy
curl -sI https://<サイト>/vault/ | grep -i content-security-policy
```

そのあとサイトを開き、開発者ツールのコンソールに CSP のエラーが出ていないかを見ます。利用上限付きのキーで、キーの保存 → チャット → パスフレーズの設定と解錠、まで一通り試してください。

Cloudflare Pages でも配信できます（ビルドコマンド `npm run build`、出力ディレクトリ `dist`）。`_headers` はどちらでも同じように効きます。

**データはオリジンごと**: 会話とキーは、開いた URL ごとに別々に保存されます。お試し用ビルドから本番へ、`workers.dev` から独自ドメインへ、などと移るときは、先に「設定 → プライバシーとデータ」でバックアップを書き出し、移った先で読み込んでください。キーは入れ直しになります。

### 厳密な構成: 金庫と取得用ページを別オリジンに置く

標準では、キー金庫（`/vault/`）と取得用ページ（`/fetch/`）はアプリと同じオリジンから配信され、どこに置いても動きます。その限界は、万一アプリ内でスクリプトが動いた（XSS）場合に、金庫にキーを求めたり、取得用ページを使って任意のアドレスへデータを送ったりできることです。どちらも別オリジンに置けば、そうしたスクリプトには何もできません。

```bash
# 金庫のサイト（dist-vault/ を配信）と取得用ページのサイト（dist-fetch/ を配信）
VITE_APP_ORIGIN=https://app.example.com npm run build:vault
VITE_APP_ORIGIN=https://app.example.com npm run build:fetch
# 本体のサイト: 2 つのオリジンは frame-src に入り、/vault/ と /fetch/ はビルドされなくなる
VITE_VAULT_URL=https://vault.example.com/ VITE_FETCH_URL=https://fetch.example.com/ npm run build
```

同じ独自ドメインのサブドメインに置いてください（Workers か Pages のサイト 3 つ、無料）。`*.workers.dev` や `*.pages.dev` の 2 つのサイトは別サイト扱いになり金庫の保存領域が制限されることがあり、`*.github.io` のページはすべて同じオリジンです。本体のプレビュー用 URL からは別オリジンの金庫を埋め込めません。キーは新しい金庫で入れ直しになります。

### ほかの静的ホスト（GitHub Pages など）

`npm run build` は各ページの CSP を `_headers` だけでなく HTML にも入れるので、`_headers` を読まないホスト（GitHub Pages）でも CSP は効きます。ただし `<meta>` の CSP に書けないものは失われます: `frame-ancestors`（ほかのサイトがページを埋め込める）、ほかのヘッダ（`nosniff`、`Referrer-Policy`、COOP）、PDF 用 Worker の CSP（`<meta>` の CSP は Worker に届きません）。普段使いには Cloudflare をおすすめします。

標準ではドメインの直下（`<ユーザー名>.github.io` という名前のリポジトリか、独自ドメイン）から配信します。`<ユーザー名>.github.io/<リポジトリ名>/` のようなパスの下に置くときは、そのパスを指定してビルドします。

```bash
VITE_BASE_PATH=/<リポジトリ名>/ npm run build
```

各ページ（`fetch/`・`vault/`・`sandbox/`）、Service Worker、アセットはすべてそのパスの下になります。`<ユーザー名>.github.io` の下のサイトはすべて同じオリジンです。ほかのリポジトリのサイトで動くスクリプトから、アプリが保存したもの（会話、金庫のキー）を読めてしまい、守れるのはパスフレーズによる暗号化だけです。できればアプリ専用のドメインに置いてください。

### Web のページを読む・ファイルを取り込む

モデルが Web に触れる方法は 2 つで、どちらも別の取得用ページ（`/fetch/`、専用の CSP）がアドレスを見せてから確認します。サイトごとに「今後確認せずに」を選べます。ページを読むときと、ファイルを取り込むときで別々に覚えます（取得用ページの保存領域に保存し、設定 → Web →「取得用ページの設定」で取り消せます）。選んだサイトへは、モデルがアドレスに何を入れても確認なしで送られます（ほかのサイトへのリダイレクトはあらためて確認します）。アプリ本体は任意のアドレスにも Jina Reader にも接続しません。取得用ページは、直接 → 中継サーバー（設定したとき）→ Jina Reader（読むときだけ）の順に試します。

- **読む**（`fetch_url`。ページから知りたいことも渡す）: ページ（HTML・テキスト・PDF）をアプリ内で本文にし、ツールのない別の呼び出しがその本文から依頼に答えます。会話のモデルに届くのはその答えだけなので、ページに仕込まれた指示の影響を受けにくくなります。読むモデルは会話と同じものか、設定 → Web の「ページの抜き出しに使うモデル」で選んだものです。直接取れないページは中継サーバー（下記）を通し、それでも取れないページと、HTML に本文がほとんどない（見える文字が 400 字ほどに満たない）ページ（スクリプトで描くもの）は Jina Reader（`r.jina.ai`）で読みます。
- **取り込む**（`fetch_file`）: ファイルや画像をそのままファイルタブに保存します。テキスト・CSV・HTML・コード・PDF はモデルが読めるファイルに、画像は画像として保存します（20 MB まで。SVG は不可）。ページの HTML を扱いたいとき（スクレイピングなど）は、保存してモデルに読ませるか、`run_javascript` で試せます。

Jina Reader はキーなしで使えます（IP アドレスごとに 1 分 20 回まで）。上限を上げたいときは、取得用ページの設定で API キーを入れます（任意）。このキーは取得用ページの保存領域に暗号化せずに保存し（パスフレーズがあっても同じ）、Jina Reader への依頼にだけ付けます。バックアップには入りません。

ブラウザから取得できるのは、それを許しているサイトだけです（CORS）。ファイルや画像の配信元（GitHub の raw ファイル、Wikimedia、多くの CDN）は許していることが多く、一般の Web ページは許していないことが多いです。そうしたサイト向けに、自分の中継サーバーを置けます（任意）。

```bash
# 中継（relay/worker.js）を自分の Cloudflare に置く。relay/wrangler.jsonc の ALLOWED_ORIGINS に取得用ページのオリジン（アプリと同じサイトならアプリのオリジン）を書く
cd relay && npx wrangler deploy
# アプリ: 中継の場所を取得用ページに伝える
VITE_FETCH_RELAY_URL=https://nobackend-fetch-relay.<アカウント>.workers.dev npm run build
# 取得用ページを別オリジンに置く場合は、build:fetch と本体の build の両方に同じ値を渡す（本体は 設定 → Web に表示する）
```

中継は公開された https のアドレスにだけ接続し、あなたのヘッダや Cookie を送らず、何も記録せず、許可したオリジンにだけ応答し、リダイレクトには自分では従わず（転送先を取得用ページに伝え、サイトの外へ出るなら取得用ページが確認します）、1 つの IP から 1 分に 30 回までという制限を Cloudflare に指定しています（オリジンはスクリプトなら偽れ、中継のアドレスはアプリのコードから読めるため）。ただし Cloudflare はこの制限を大まかにしか適用せず、試したときはすべて通りました。中継を通したアドレスは中継（自分の Worker）にも見えます。

### 実験的機能: ページから Web・ファイル・モデルを使う（自己責任）

自分用のビルドに限ります。`VITE_EXPERIMENTAL_PAGE_API=1` を付けてビルドすると、ファイルタブで表示した、フォルダー内の HTML のページ（モデルが試すページは除く）で次が使えます。

- `nbl.files.list()`・`nbl.files.read(path)`・`nbl.files.write(path, text)`: そのページのサイトのファイル（パスはサイトの一番上から。書き込みはテキストだけ）。
- `nbl.chat(prompt, { system })`: 新しいチャットで使うモデルの答えの本文（ツールなし。1 分 20 回まで。費用はほかと同じく記録されます）。
- `VITE_FETCH_RELAY_URL` も設定したとき: https のアドレスへの `fetch(url)`（GET だけ）。取得用ページを通し、1 件ごとに確認します（サイトごとに「今後確認しない」も選べ、ページを読む・取り込むとは別に覚えます）。https のアドレスの `<img>` も同じように取得します。

```bash
VITE_EXPERIMENTAL_PAGE_API=1 VITE_FETCH_RELAY_URL=https://nobackend-fetch-relay.<アカウント>.workers.dev npm run build
```

ページがアドレスに入れたもの（サイトのファイルも含む）はそのサイトに送られ、確認しないと選んだサイトには確認なしで送られます。ページからのモデルの呼び出しには費用がかかります。このビルドを他人向けに公開しないでください。

### ビルド時に接続先を足す

`VITE_CUSTOM_PROVIDERS` に、OpenAI 互換の接続先を JSON の配列で指定します。接続先の一覧・金庫の送り先・CSP に自動で入ります。

```bash
VITE_CUSTOM_PROVIDERS='[{"id":"ollama","label":"Ollama","baseUrl":"http://localhost:11434/v1","keyOptional":true}]' npm run build
```

| 項目 | 意味 |
|---|---|
| `id` | 半角の小文字・数字・ハイフン |
| `label` | 表示名（省略すると `id`） |
| `baseUrl` | https（http はローカルのみ） |
| `keyOptional` | キーなしで使える |
| `publicModels` | モデル一覧をキーなしで取れる |

指定が不正だとビルドが止まります。接続先がこのサイトからの通信（CORS）を許可している必要があり、Ollama なら `OLLAMA_ORIGINS=https://<サイト>` を付けて起動します。キーの送り先をビルド時に固定しているので、画面から接続先を足すことはできません。

## パスフレーズ（キーと会話の保護）

保存方法を選ぶ必要はありません。

- **パスフレーズがなければ**、キーも会話もそのまま保存します。
- **パスフレーズを設定すると**:
  - API キー・会話・ファイル・画像・保存済みのプロンプト・スキルを暗号化します（取得用ページが持つ Jina Reader のキーと確認しないサイトは除く）。
  - 解錠するまで、アプリ全体をロック画面で隠します。
  - タブごと、読み込み直すたびに解錠が必要です。
  - サイドバーのボタンでロックでき、操作がないときの自動ロックも設定できます。
- **設定のしかた**: 最初のキーを保存した直後に、設定するかを一度だけ案内します（「あとで」で飛ばせます）。設定の「接続とキー」から、いつでも設定・変更・解除できます。変更と解除には今のパスフレーズが必要です。
- **忘れると元に戻せません。** ロック画面から、すべて削除してやり直すことだけができます。
- **バックアップは、書き出すときにパスワードを設定しない限り平文の JSON です**（パスフレーズを設定していれば既定で暗号化）。平文のバックアップは保管に気をつけてください。

## API キーの安全な使い方

**利用上限のあるキー**を使ってください。万一漏れても、被害額は上限で止まります。

- **Venice**: **INFERENCE** タイプのキーを作り、1 日の利用上限と有効期限を設定します。`modelPrivacy: PRIVATE_ONLY` にすると、外部の事業者へ中継されるモデルを使えなくなります。
- **OpenRouter**: キーにクレジットの上限を設定します。
- **Anthropic**: Console でワークスペースの利用上限を設定します。
- **Gemini**: 無料枠では、送った内容が Google のサービス改善に使われることがあります（有料枠では使われません）。
- **DeepSeek**: プリペイド式なので、チャージした額が上限です。データは中国の事業者のサーバーで処理されます。
- **Groq**: 無料枠には回数とトークン数の上限があります。有料にする場合は利用上限を設定してください。
- **NanoGPT**: キーに日・週・月の利用額の上限を設定してください。
- **DeepInfra**: キーに月の利用額の上限を設定してください。
- **Cerebras**: プリペイドのクレジット制なので、残高が上限になります。
- **Novita**: キーに予算（利用額の上限）を設定してください。
- **Chutes**: キーごとの利用額の上限は確認できていません。少額のチャージで使ってください。
- **Together**: プリペイドで、キーごとの上限はありません。少額のチャージで使ってください。
- **Tavily**（ツール方式の Web 検索）: 利用上限を設定します。
