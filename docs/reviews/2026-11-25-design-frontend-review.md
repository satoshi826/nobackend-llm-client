## 総評
- **よいところ**: プライバシーを軸にした情報設計（送信先の表示、ツールの承認、空状態の文言）。ストリーミングの更新を 1 フレームにまとめていること。アニメーションを減らす設定に一部対応していること。
- **主な弱点**:
  - モーダル類のフォーカス管理がない。
  - ダークモードで、補助のテキストと、フォーカスの表示が弱い。
  - 長い会話とギャラリーで描画のコストが大きい。
  - 入力欄や注意書きのスタイルが、あちこちに複製されている。

## 1. 見た目と操作

### 情報の構成
- 設定の「チャット」タブに、テーマ・温度・返信候補・画像・圧縮が同居している。
- 「すべての API キーを削除」が 2 か所にあり、確認のしかたも違う。
- 文脈の使用率の表示を押すと、確認なしで（課金のある）圧縮が始まる（`ChatView.tsx:82-91`）。
- サイドバーの下部に、ラベルつきのボタンとアイコンだけのボタンが混在している。

### 初回の流れ
- モバイルでは、初回の 2 つの画面にヘッダーがないので、サイドバーや設定に行けない（バックアップから戻せない）。
- 何段階目にいるかの表示と、戻る導線がない。「はじめに」の文が重複している。

### ロック画面とキー金庫の埋め込み
- 解錠の入力欄に、自動でフォーカスが入らない（`vault/main.ts:103-115`）。
- 解錠に失敗すると、画面全体を描き直すので、入力した値とフォーカスが消える。
- ダークモードで、金庫の枠の背景（`#18181b`）が周り（zinc-950）と合わない。
- 読み込み中の表示と、失敗したときの表示がない。高さが 280px から伸び縮みしてガタつく。
- テーマを変えても追従しない。
- キーを 1 つ削除するときは確認がない（すべて削除には確認がある）。
- 絵文字の 🔑🔒 と SVG のアイコンが混在している。

### 状態の伝え方
- トーストが入力欄と重なる。画面下の安全領域（ノッチなど）に対応していない。
- 会話名の変更が、フォーカスが外れると取り消される（タッチ操作で事故が起きやすい）。
- 使用量のグラフは、マウスを乗せないと値が見えない（タッチやキーボードでは見られない）。

### 画像の UI
- 画像バーのセレクトが小さすぎる（高さ約 22px）。1 文字打つたびに設定を保存している。

### 表記の揺れ
- 同じものを指す `copyOf` の引き方が 2 通りある。PrivacyBadge が 2 つ実装されていて、文言も違う。
- `private` と `tok` が英語のまま混ざっている。

## 2. アクセシビリティ
- **フォーカス**:
  - Modal・ConfirmDialog・拡大表示に、フォーカスを中に閉じ込める処理、閉じたあとに元へ戻す処理、背景を操作できなくする処理（inert）がない。
  - 最初のフォーカスが「閉じる」ボタンに入る。
  - モバイルで閉じたサイドバーが、Tab キーでたどる順番に残っている。
- **フォーカスの見た目**: 検索欄と入力欄で、フォーカスしていることがわかりにくい。素の `<button>` に `focus-visible` の指定がない。
- **ARIA**:
  - タブに矢印キーでの移動と `aria-controls` がない。
  - タブではないもの（切り替えボタン）に `role="tab"` を使っている。
  - メニューと候補一覧を、キーボードで操作できない。
  - 選択中のモデルを `aria-pressed` で表している（`aria-current` が適切）。
  - トーストが、出すたびに読み上げ用の領域ごと差し込まれるので、読み上げられない可能性がある。
  - 承認カードが出ても、通知もフォーカスの移動もない。
- **コントラスト**: ダークモードの `text-zinc-500` が約 3.6〜4.1:1。11px の `zinc-400` が約 2.6:1。金庫の危険ボタンが約 2.7:1。
- **動きとタッチ**: アニメーションを減らす設定に一部まだ対応していない。会話の行の操作ボタンが約 22px 四方で、指で押すには小さい。

## 3. フロントエンドの実装
- **描画の性能**:
  - ストリーミング中、毎フレームすべてのメッセージを描き直している（`MessageItem` がメモ化されておらず、兄弟の検索でメッセージ全体を毎回なめている）。
  - 長い文章では、Markdown の変換を毎フレーム全文やり直す。
  - 一覧の仮想化（見えている部分だけ描く工夫）がない。
  - ギャラリーは、開いた瞬間にすべての画像を原寸で復号する。表示用に作った画像の URL を解放していない。
  - モデル選択は、1 文字打つたびにすべての行を描き直す。
- **構造**:
  - `ChatView.tsx`（578 行）と `SettingsModal.tsx`（545 行）が大きすぎる。
  - UI から DB の層を直接呼んでいる。
  - `state/app.ts` が状態をすべてまとめて書き出していて、境界がない。
  - スタイルが重複している。
- **多言語化**: 文言がすべて JSX に直接書かれている。日付や通貨の書式を手で組み立てている。
- **テスト**: コンポーネントのテストがない。状態の判定ロジックが JSX の中に埋もれている。

### デザイントークンと部品の指針（案）
- **色（役割で名前を付ける）**:
  - 面と線と文字: `surface` / `surface-raised` / `border` / `border-strong` / `text` / `text-muted`
  - 意味の色: `accent`（sky）、`skill`（violet）、`image`（fuchsia）、`ok` / `warn` / `danger`
  - キー金庫の CSS 変数も、同じ値にそろえる。
- **文字の大きさ**: 本文 15/28px、`sm` 14px、補助 12px、極小 11px（バッジ専用）。任意の値は使わない。
- **角の丸み**: 操作部品は `rounded-lg`、カードは `rounded-xl`、シートと入力欄は `rounded-2xl`、チップは `rounded-full`。
- **高さ**: 操作部品は 32px と 36px。タッチ操作では 40px 以上。
- **重なり順（z-index）**: サイドバー 30 → モーダル 40 → 確認ダイアログと処理中の表示 60 → 拡大表示 70 → トースト 80。
- **部品の使い分け**:
  - アイコンだけのボタンは `IconButton` にして、ラベルを必須にする。
  - オン・オフは `aria-pressed`、どれか 1 つを選ぶものは `Segmented`（radiogroup）、画面の切り替えは `Tabs`。
  - 取り消せない操作は、必ず `askConfirm` を通す。
  - アニメーションは `motion-safe:` を前提にする。
